# 3 任务二：大语言模型越狱攻击（GCG）算法复现

本任务希望让大家初步接触**大语言模型（LLM）及其安全问题**，亲手实现一个经典的大模型越狱攻击算法。考虑到算力资源有限，本作业不需要复现论文的完整规模实验，重点考察的是**对模型与算法本身的理解**，以及对大模型实际运行流程的体感。因此，代码补全部分挖空集中在算法核心步骤，实验部分也只要求跑少量样本即可。

## 环境配置

由于 GCG 攻击需要对模型反复做前向和反向传播，建议使用 GPU 运行。可以参考以下方式：

1. 在 **ModelScope（魔搭）** 上开一个 Notebook / GPU 实例，新用户有约 **36 小时免费 GPU 使用时长**，超出后需付费，请合理规划。
2. ModelScope 实例自带 Python 环境，**选择 torch 2.3.1 对应的镜像**即可。
3. 作业提供的 `requirements.txt` **不需要全部安装**，实例环境里大部分依赖已经具备，通常只需额外安装：
   ```bash
   pip install litellm==1.53.7 wordfreq
   ```
   （`wordfreq` 不需要指定版本。）
4. 攻击所用的目标模型为 **`qwen/qwen-2.5-1.5B-Instruct`**，可直接在 ModelScope 环境内从魔搭下载（无需翻墙）：

   ```
   modelscope download --model Qwen/Qwen2.5-1.5B-Instruct --local_dir /YOUR WORKSPACE PATH/model/Qwen/Qwen2.5-1.5B-Instruct
   ```

> 建议：**先在本地把 TODO 代码填好、检查无误**，最后再把代码整体复制到 GPU 实例中运行，以节省宝贵的免费 GPU 时长。

## 任务说明

1. 请先阅读指定论文，再补全 `gcg` 文件夹下 `algorithm.py` 与 `loss_function.py` 中空缺的核心代码，使 GCG 攻击能够对 Qwen2.5-1.5B-Instruct 成功生成对抗后缀。论文：*Universal and Transferable Adversarial Attacks on Aligned Language Models*，Zou et al.，2023（arXiv:2307.15043）。

2. 请介绍这篇论文，包含**威胁模型**（例如攻击者的能力和可掌握的知识，如是否需要白盒访问、是否需要梯度等）、**核心算法**、**算法的优缺点**（论文中作者提到的以及你自己的分析都可以），做一个**不超过 1000 字**的概述。

3. 根据论文中 Greedy Coordinate Gradient 的思想，补全代码中所有 TODO 位置，并使代码运行成功。需要补全代码的位置有：

   (1). `loss_function.py` — `compute_loss`：实现 GCG 的逐 token 损失，即目标字符串的负对数似然（逐 token 交叉熵），注意返回未规约（`reduction="none"`）的逐 token loss。

   (2). `algorithm.py` — `compute_token_gradient` 的 TODO (1)(2)：用 one-hot 矩阵乘 embedding 权重构造一个**可微的输入**，并通过 `torch.autograd.grad` 提取损失对 one-hot 矩阵的梯度（即 token 梯度）。

   (3). `algorithm.py` — `sample_ids_from_grad` 的 TODO (3)：根据 token 梯度，为每个位置选出 top-k 个最有希望的替换 token（注意梯度符号——越负代表替换后 loss 下降越多）。

   (4). `algorithm.py` — `run` 主循环的 TODO (4)：在评估完所有候选后，**贪心地**选出 loss 最低的那一个候选，提交为本轮的最优解。

4. 运行代码完成两部分实验：

   (1). **基线（无攻击）**：先在不附加对抗后缀的情况下，测量模型对有害问题的输出。
   (2). **GCG 攻击**：用补全后的代码对少量有害问题生成对抗后缀（保存为 `suffixes.json`），再附加后缀重新观察输出。

   > 注意：对**每一个输入 prompt** 做一次 GCG 对抗优化大约需要 **20 分钟左右**，因此**只需要跑几个样本即可**，不必跑完整数据集。

5. 利用提供的 `test_suffix.py`，对照观察**有无对抗后缀时模型输入与输出的变化**。请挑选 **5 个攻击样本**进行分析：说明原始有害问题、生成的对抗后缀、模型在无后缀 / 有后缀两种情况下的回复差异，并把观察到的具体输入输出结果粘贴到报告中。

6. 思考：通过观察GCG当前的算法输出，一些失败案例，有什么问题没有？这些问题是由GCG算法本身引起还是大模型能力引起？（可以粘贴一些现象在报告中）如果希望进一步**提升攻击成功率、攻击效率（减少查询/优化步数），或提升对抗后缀的隐蔽性**，可以如何优化当前算法？可以给出思考，也可以做进一步的小实验验证（例如调整 `search_width`、`topk`、`num_steps` 等超参并对比）。
